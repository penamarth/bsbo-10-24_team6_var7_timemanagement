# Прецедент «Учет затраченного рабочего времени»

## Рамки
Система учета рабочего времени (Taskly).

## Уровень
Задача пользователя.

## Основной исполнитель
Сотрудник.

## Заинтересованные лица и их требования
- Сотрудник. Хочет удобно фиксировать в рамках одного приложения рядом с задачей, 
  сколько часов и на какой тип деятельности он потратил время.
- Руководитель. Хочет видеть кто фактически, сколько времени потратил 
  в конкретный день на задание — для контроля загруженности и отчетности.
- Организация. Хочет достоверные данные
  о трудозатратах по каждому заданию.

## Предусловия
Программа запущена, пользователь вошел в систему.
Открыты данные существующего задания.
Задание находится в статусе «В работе» —
списывать время можно только на активное задание.

## Результаты (постусловия)
- Новая запись о затраченном времени создана
  и связана с заданием: дата, количество часов,
  тип активности, автор.
- Суммарное время, списанное на задание, обновлено.
- Записи доступны для мониторинга загруженности (UC2)
  и формирования отчетов (UC5).

## Основной успешный сценарий
1. Сотрудник запрашивает данные учета времени
   по заданию.
2. Система возвращает список записей времени,
   связанных с заданием: дата, количество часов,
   тип активности, автор.
3. Сотрудник передает новую запись:
   количество часов, тип активности, дату.
4. Система проверяет, что задание находится
   в статусе «В работе».
5. Система проверяет, что все поля заполнены
   и количество часов — положительное число.
6. Система проверяет, что указанная дата находится
   не ранее чем за 3 дня до текущей.
7. Система проверяет, что суммарное время
   сотрудника за указанную дату с учетом новой
   записи не превышает 8 часов.
8. Система создает запись, фиксирует автором
   текущего пользователя и связывает запись
   с заданием.
9. Система включает запись в учет времени задания
   и обновляет суммарное списанное время.
10. Если записей несколько, сотрудник повторяет
    шаги 3–9 для каждой.

## Альтернативные сценарии
- Шаг 2. Записей по заданию еще нет.
  Система возвращает пустой список;
  добавление записей доступно при статусе
  «В работе».
- Шаг 4. Задание не в статусе «В работе»
  (еще «Предложена» или уже «Завершена»).
  Система отклоняет запись: списывать время
  можно только на задание в работе.
- Шаг 5. Заполнены не все поля или количество
  часов некорректно (ноль, отрицательное число
  или не число).
  Система не создает запись и сообщает причину.
- Шаг 6. Указана дата раньше, чем три дня назад.
  Система не создает запись и сообщает,
  что время можно списывать не более чем
  за три последних дня.
- Шаг 7. Лимит превышен: сумма часов сотрудника
  за указанную дату вместе с новой записью
  превышает 8 часов.
  Система не создает запись и сообщает,
  сколько часов еще можно списать за эту дату.
- Шаги 3–8. Сотрудник отменяет добавление записи.
  Данные не сохраняются.
- После шага 8. Сотрудник удаляет ошибочную запись.
  Система удаляет запись и пересчитывает
  суммарное время; при необходимости сотрудник
  добавляет исправленную запись заново.

## Частота использования
Ежедневно, по несколько раз в день —
по мере выполнения работы.

## Открытые вопросы
- Какие типы активности входят в список
  и кто его определяет?
- Можно ли редактировать существующую запись
  или только удалять и создавать заново?
- С каким шагом вводятся часы (сотые доли,
  полчаса) и есть ли минимальное значение?
- Нужно ли хранить историю удаленных записей
  и видит ли ее руководитель?
