# Прецедент «Создание задания»

## Рамки
Система учета рабочего времени (Taskly).

## Уровень
Задача пользователя.

## Основной исполнитель
Руководитель.

## Заинтересованные лица и их требования
- Руководитель. Хочет быстро сформулировать задачу,
  назначить ее конкретному сотруднику
  и видеть, что задача передана в работу.
- Сотрудник. Хочет получить понятное задание:
  с названием, описанием, сроком выполнения
  и всеми необходимыми файлами и данными.
- Организация. Хочет, чтобы все задачи сотрудников
  были зафиксированы в системе,
  а не переданы устно или в мессенджерах.

## Предусловия
Программа запущена, руководитель вошел в систему.
В системе есть хотя бы один сотрудник,
которому можно назначить задачу.

## Результаты (постусловия)
- Задача сохранена со всеми заполненными
  обязательными полями и имеет статус «Предложена».
- Создателем задачи зафиксирован текущий
  руководитель, исполнителем — выбранный сотрудник.
- К задаче прикреплены указанные файлы,
  они доступны из данных задачи.
- Задача доступна руководителю в списке
  созданных им задач.
- Задача доступна исполнителю в списке
  назначенных ему заданий.

## Основной успешный сценарий
1. Руководитель инициирует создание новой задачи.
2. Система предоставляет список сотрудников
   для выбора исполнителя.
3. Руководитель передает данные задачи: название,
   описание, срок выполнения и исполнителя;
   при необходимости — один или несколько файлов.
4. Система проверяет, что операцию выполняет
   пользователь с правами руководителя.
5. Система проверяет обязательные данные:
   название заполнено, исполнитель выбран,
   срок указан и не находится в прошлом.
6. Система создает задачу со статусом «Предложена»
   и фиксирует ее создателем текущего пользователя.
7. Система связывает переданные файлы с задачей.
8. Система сохраняет задачу в хранилище задач.
9. Задача становится доступна руководителю
   в списке созданных им задач и исполнителю —
   в списке назначенных ему заданий.

## Альтернативные сценарии
- Шаг 4. Пользователь не является руководителем.
  Система отклоняет операцию и сообщает
  о недостатке прав.
- Шаг 5. Обязательные данные не заполнены
  или некорректны:
  - не введено название задачи;
  - не выбран исполнитель;
  - срок выполнения не указан
    либо указана дата в прошлом.

  Система не создает задачу и сообщает,
  какие данные требуется исправить;
  введенные данные сохраняются
  для повторной отправки.
- Шаг 5. Задача с таким названием уже существует.
  Система предупреждает о возможном дубликате
  и запрашивает подтверждение создания.
- Шаг 7. Файл не удалось прикрепить
  (файл слишком большой или тип файла
  не поддерживается).
  Система сообщает причину; остальные файлы
  и данные задачи сохраняются.
- До шага 6. Руководитель отменяет создание задачи.
  Система отбрасывает введенные данные;
  задача не создается.

## Открытые вопросы
- Есть ли ограничение на размер и типы
  прикрепляемых файлов?
- Нужно ли уведомлять сотрудника о появлении
  новой задачи (и как именно — внутри программы,
  по почте)?
- Можно ли создать задачу без срока («когда-нибудь»)
  или срок обязателен всегда?
- Можно ли после создания переназначить задачу
  на другого сотрудника?
