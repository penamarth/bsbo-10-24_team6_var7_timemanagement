# Прецедент «Создание задания»

## Рамки
Система учета рабочего времени (Taskly).

## Уровень
Задача пользователя.

## Основной исполнитель
Руководитель.

## Заинтересованные лица и их требования
- Руководитель. Хочет быстро сформулировать задачу,
  назначить ее конкретному сотруднику
  и видеть, что задача передана в работу.
- Сотрудник. Хочет получить понятное задание:
  с названием, описанием, сроком выполнения
  и всеми необходимыми файлами и данными.
- Организация. Хочет, чтобы все задачи сотрудников
  были зафиксированы в системе,
  а не переданы устно или в мессенджерах.

## Предусловия
Программа запущена, руководитель вошел в систему.
В системе есть хотя бы один сотрудник,
которому можно назначить задачу.

## Результаты (постусловия)
- Задача сохранена со всеми заполненными
  обязательными полями и имеет статус «Предложена».
- К задаче прикреплены указанные файлы,
  они доступны из карточки задачи.
- Задача отображается у руководителя
  в разделе созданных задач.
- Задача появляется в кабинете назначенного сотрудника
  в его личном списке задач.

## Основной успешный сценарий
1. Руководитель открывает раздел «Задачи».
2. Нажимает кнопку «Создать задачу».
3. Система показывает форму новой задачи.
4. Вводит название и описание задачи.
5. Указывает срок выполнения
   (выбирает дату из календаря).
6. Выбирает исполнителя из списка сотрудников.
7. Если к задаче нужно приложить материалы,
   нажимает «Прикрепить файл» и выбирает один
   или несколько файлов;
   система показывает список прикрепленных файлов.
8. Нажимает «Сохранить».
9. Система проверяет заполнение обязательных полей,
   сохраняет задачу в статусе «Предложена»
   и показывает ее в списке созданных задач.
10. Задача появляется в кабинете назначенного сотрудника.

## Альтернативные сценарии
- Шаг 9. Не заполнены обязательные поля.
  Система не сохраняет задачу, подсвечивает
  проблемные поля и сообщает причину:
  - не введено название задачи;
  - не выбран ни один исполнитель;
  - срок выполнения не указан
    либо указана дата в прошлом.

  Введенные данные остаются в форме
  для исправления; после исправления
  руководитель снова нажимает «Сохранить».
- Шаг 7. Файл не удалось прикрепить
  (файл слишком большой или тип файла
  не поддерживается).
  Система сообщает причину,
  остальные файлы и поля формы сохраняются.
- Шаг 7. Руководитель передумал прикреплять файл.
  Нажимает «Удалить» рядом с прикрепленным файлом
  в списке, файл убирается из задачи.
- До шага 8. Руководитель решает не создавать задачу.
  Нажимает «Отмена», система закрывает форму
  без сохранения.
- Шаг 9. Задача с таким названием уже существует.
  Система предупреждает о возможном дубликате
  и предлагает подтвердить создание
  либо вернуться к редактированию.

## Открытые вопросы
- Есть ли ограничение на размер и типы
  прикрепляемых файлов?
- Нужно ли уведомлять сотрудника о появлении
  новой задачи (и как именно — внутри программы,
  по почте)?
- Можно ли создать задачу без срока («когда-нибудь»)
  или срок обязателен всегда?
- Можно ли после создания переназначить задачу
  на другого сотрудника?
