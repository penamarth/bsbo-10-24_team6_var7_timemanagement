# Прецедент «Работа с заданием»

## Рамки
Система учета рабочего времени (Taskly).

## Уровень
Задача пользователя.

## Основной исполнитель
Сотрудник.

## Заинтересованные лица и их требования
- Сотрудник. Хочет видеть назначенные ему задания,
  видеть по ним подробную информацию, иметь возможность для предоставления 
  результатов путем добавления в описание или прикреплением файла, а также отмечать ход выполнения
  сменой статуса.
- Руководитель. Хочет, чтобы сотрудники вовремя
  приступали к заданиям и поддерживали актуальность
  статусов.
- Организация. Хочет централизованно хранить задания 
  и их результаты включая текущие статусы для контроля поручений.

## Предусловия
Программа запущена, сотрудник вошел в систему.
Системе известно, какие задания назначены
этому сотруднику.

## Результаты (постусловия)
- Сотруднику возвращен список назначенных
  ему заданий.
- По выбранному заданию возвращены полные данные:
  название, описание, срок, статус, файлы.
- Если сотрудник изменил описание — в данных
  задания сохранено новое описание.
- Если сотрудник добавил файлы — они связаны
  с заданием.
- Если сотрудник начал выполнение — задание
  получило статус «В работе».
- Если сотрудник завершил выполнение — задание
  получило статус «Завершена».
- Актуальное состояние задания доступно
  руководителю.

## Основной успешный сценарий
1. Сотрудник запрашивает список назначенных
   ему заданий.
2. Система находит в хранилище задания,
   назначенные текущему сотруднику, и возвращает
   список: название, срок выполнения, текущий статус.
3. Сотрудник выбирает задание и запрашивает
   его данные.
4. Система возвращает полные данные задания:
   название, описание, срок выполнения,
   текущий статус и список прикрепленных файлов.
5. Если задание в статусе «Предложена», сотрудник
   инициирует начало выполнения.
6. Система проверяет допустимость перехода
   и переводит задание в статус «В работе».
7. При необходимости сотрудник передает
   измененное описание; система обновляет
   описание задания.
8. При необходимости сотрудник передает файлы;
   система создает вложения и связывает их
   с заданием.
9. По завершении работы сотрудник инициирует
   завершение задания.
10. Система проверяет допустимость перехода
    и переводит задание в статус «Завершена».

## Альтернативные сценарии
- Шаг 2. Сотруднику не назначено ни одного задания.
  Система возвращает пустой список.
  Прецедент завершается без изменений.
- Шаг 3. Сотрудник выбирает другое задание.
  Сценарий продолжается с шага 3
  для другого задания.
- Шаг 6. Задание уже в статусе «В работе».
  Система оставляет статус без изменений;
  сотрудник продолжает с шага 7.
- Шаг 6. Задание в статусе «Завершена».
  Система отклоняет переход: завершенное задание
  нельзя вернуть в работу.
- Шаг 7. Сотрудник отменяет изменение описания.
  Данные задания не изменяются.
- Шаг 8. Файл не удалось прикрепить
  (файл слишком большой или тип файла
  не поддерживается).
  Система сообщает причину; ранее прикрепленные
  файлы остаются без изменений.
- Шаг 10. Задание еще в статусе «Предложена».
  Система отклоняет завершение:
  сначала нужно начать выполнение задания.
- Шаг 10. Задание уже в статусе «Завершена».
  Система сообщает, что задание
  было завершено ранее.
- Между шагами 6–9. Сотрудник списывает
  затраченное время на задание.
  Действия описаны в прецеденте
  «Учет затраченного рабочего времени» (UC4).

## Специальные требования
- Сотрудник видит только задания,
  назначенные ему лично.
- Статусы меняются только по цепочке:
  «Предложена» → «В работе» → «Завершена».
- Нельзя завершить задание, не начав его;
  нельзя вернуть завершенное задание в работу.
- Редактирование описания и прикрепление файлов
  не меняют статус задания.
- Каждый файл прикреплен к конкретному заданию
  и не смешивается с файлами других заданий.
- Действия с заданием не затрагивают другие задания
  сотрудника.
- Списание рабочего времени — отдельный прецедент
  «Учет затраченного рабочего времени» (UC4).

## Частота использования
Регулярно в течение рабочего дня: при получении
новых заданий, в ходе выполнения текущих
и при их завершении.

## Открытые вопросы
- Можно ли редактировать описание задания
  после его завершения?
- Можно ли добавлять, удалять или заменять файлы
  после завершения задания?
- Нужен ли просмотр и скачивание прикрепленных
  файлов прямо из данных задания?
- Какие типы файлов допустимы и есть ли
  ограничение на размер?
- Нужно ли хранить историю изменений описания
  и статусов задания?
- Уведомлять ли руководителя о смене статуса,
  изменении описания и добавлении файлов?
- Можно ли завершить задание, если на него
  не списано ни одного часа?
- Что происходит, если руководитель удаляет
  или переназначает задание, пока сотрудник
  с ним работает?
